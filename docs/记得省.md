# 记得省系统接口文档

基础路径：{API_HOST}/open/v1

请求方式均为 POST，Content-Type: application/json。业务是否成功以响应体 code 为准，0 表示成功。

## 公共约定

除「生成签名」外，每个请求都要带：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| userNo | string | 是 | 代理编号 |
| timestamp | integer | 是 | 13 位毫秒时间戳，与服务器相差不超过 5 分钟 |
| sign | string | 是 | 签名，大写 MD5 |

调用方出口 IP 须配置在代理后台白名单中。账户状态须为 Activated。

统一响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": 1730000000000
}
```

失败时 data 为 null。

## 签名

1. 取全部参数，去掉 sign，再去掉 null 和空字符串。数字 0 参与签名。

2. 参数名按 ASCII 升序排序，拼成 key=value&key=value。

3. 末尾拼接 &secretKey={商户密钥}。密钥不要放进请求体。

4. 对整个字符串做 MD5，转为大写。

```
timestamp=1730000000000&userNo=A10001&secretKey=demoSecretKey
```

结果：715022C7544A5D7799DA05F236BF79DF

多个值用英文逗号拼成一个字符串，例如 carrier=1,2。下单响应 data.sign 和订单回调 sign 使用同一算法，验签时去掉 sign 和空字段。

## 错误码

| code | 说明 |
|---|---|
| 0 | 成功 |
| 1001 | 用户不存在 |
| 1002 | 签名不正确 |
| 1003 | 请求已过期或时间戳无效 |
| 1004 | 缺少 userNo、timestamp 或 sign |
| 1005 | 账户未激活 |
| 1006 | IP 不在白名单内 |
| 2001 | 参数错误 |
| 2002 | 缺少必填参数，或号码黑名单、运营商不匹配、电费缺地区、卡密不可下单 |
| 2003 | 未查询到数据，或订单不属于本账户 |
| 3001 | 重复提交 |
| 3002 | 产品已下架 |
| 3003 | 下单失败，具体原因见 message |
| 3006 | 撤单失败 |
| 9000 | 服务错误。商品查询过快时 message 为「查询太频繁」 |
| 9001 | 系统维护，API 暂不可用 |

## 订单状态

| 状态 | 说明 |
|---|---|
| CREATED | 未充值 |
| PROCESSING | 充值中 |
| PENDING_SUPPLEMENT | 压单 |
| SUCCESS | 充值成功 |
| FAILED | 充值失败、撤单退款、返销 |

CREATED、PROCESSING、PENDING_SUPPLEMENT 不是终态。

## 生成签名

`POST /open/v1/generateSign`

调试接口，不校验签名和 IP。正式环境请在接入方服务器本地计算签名。

请求至少包含 userNo，其余字段会一并参与签名。

```json
{
  "userNo": "A000012"
}
```

响应 data 包含服务端生成的 timestamp、sign，以及请求中的原字段。

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "sign": "1A3983136DF7D178BF6D00E5771E159D",
    "timestamp": 1764251084843,
    "userNo": "A000012"
  },
  "timestamp": 1764251084926
}
```

## 下单

`POST /open/v1/checkout`

code = 0 表示受理成功并已冻结金额，不表示充值成功。最终结果以回调或查单为准。未收到明确失败时，不要自行把订单判为失败，应通过查单核对。

clientOrderNo 全平台唯一，重复返回 3001。话费、流量会校验号码归属地。电费必须同时传 area、city。卡密类不能通过本接口下单。余额不足返回 3003。

请求：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| userNo | string | 是 | 代理编号 |
| timestamp | integer | 是 | 时间戳 |
| sign | string | 是 | 签名 |
| productId | string | 是 | 产品编号 |
| phone | string | 是 | 充值号码。电费为电费账号 |
| clientOrderNo | string | 是 | 接入方订单号 |
| notifyUrl | string | 是 | 结果回调地址 |
| owner | string | 否 | 机主姓名 |
| area | string | 电费必填 | 省份 |
| city | string | 电费必填 | 城市 |

```json
{
  "userNo": "A000012",
  "productId": "1",
  "phone": "15186817850",
  "clientOrderNo": "7218D3FE-9A3C-2126-655B-E568BD662E5A",
  "notifyUrl": "https://merchant.example.com/notify",
  "timestamp": 1767950404321,
  "sign": "A4EB9DE2796CA8D30E069263D56E2F6E"
}
```

响应 data：

| 字段 | 类型 | 说明 |
|---|---|---|
| userNo | string | 代理编号 |
| orderNo | string | 平台订单号 |
| clientOrderNo | string | 接入方订单号 |
| phone | string | 充值号码 |
| totalAmount | number | 订单金额，元 |
| timestamp | integer | 参与 data.sign 的时间戳 |
| sign | string | 对 data 中除 sign 外的非空字段签名 |

```json

  "message": "提单成功！",
  "data": {
    "userNo": "A000012",
```

## 撤单

`POST /open/v1/cancel`

撤销本账户一笔未完成订单。orderNo 与 clientOrderNo 至少填一个；都填时必须是同一笔。一次只能撤一笔。

| 结果 | 说明 |
|---|---|
| finished = true | 已失败并退款，随后查单为 FAILED |
| finished = false | 已受理，当前轮次结束后失败退款。此前查单仍可能是 PROCESSING |

已终态订单返回 3006。订单不存在或不属于本账户返回 2003。同一单号 5 秒内重复提交返回 3001。

请求：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| userNo | string | 是 | 代理编号 |
| timestamp | integer | 是 | 时间戳 |
| sign | string | 是 | 签名 |
| orderNo | string | 否 | 平台订单号 |
| clientOrderNo | string | 否 | 接入方订单号 |

```json
{
  "userNo": "A000012",
  "clientOrderNo": "CF0BD09D-B51E-2BFE-E8CE-E1D5ED08DC10",
  "timestamp": 1767953553237,
  "sign": "按全部非空字段计算"
}
```

响应 data：

| 字段 | 类型 | 说明 |
|---|---|---|
| userNo | string | 代理编号 |
| orderNo | string | 平台订单号 |
| clientOrderNo | string | 接入方订单号 |
| finished | boolean | 是否已经失败退款 |

```json
{
  "code": 0,
  "message": "撤单成功，已失败退款",
  "data": {
    "userNo": "A000012",
    "orderNo": "C26010917235685200215B5",
    "clientOrderNo": "CF0BD09D-B51E-2BFE-E8CE-E1D5ED08DC10",
    "finished": true
  },
  "timestamp": 1767953564183
}
```

等待结束时：

```json
{
  "code": 0,
  "message": "已标记撤单，等待轮询结束",
  "data": {
    "userNo": "A000012",
    "orderNo": "C26010917235685200215B5",
    "clientOrderNo": "CF0BD09D-B51E-2BFE-E8CE-E1D5ED08DC10",
    "finished": false
  },
  "timestamp": 1767953564183
}
```

## 订单回调

接入方须在 5 秒内返回 HTTP 200，且响应体为以下任一形式：

文本 ok 或 success，不区分大小写

JSON { "success": true } 或 { "code": 0 }

## 自来单

自来单由客客帮、蜜蜂主动调用。签名与商户接口不同，须在 5 秒内返回。地址配置在对应渠道的推单地址、查单地址。

查单状态：

| status | 说明 |
|---|---|
| 1 | 充值中、未充值 |
| 2 | 充值成功、部分成功 |
| 3 | 充值失败、取消 |
| 4 | 订单不存在（仅蜜蜂查单） |

### 客客帮签名

除 sign、datas 外，参数名升序，按 key=value 直接拼接，中间不加 &，末尾接 AppSecret，MD5 小写。

```
app_key=kk_keytarget=13800138000timestamp=1730000000user_order_id=KK10001{AppSecret}
```

### 客客帮推单

`POST /open/v1/kk/push`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| app_key | string | 是 | 渠道密钥标识，对应已开启的客客帮推单配置 |
| sign | string | 是 | 签名 |
| timestamp | string | 是 | 时间戳 |
| user_order_id | string | 是 | 客客帮订单号 |
| target | string | 是 | 充值号码，至少 7 位 |
| goods_id | string | 否 | 商品编号 |
| goods_name | string | 否 | 商品名称 |
| datas | object | 是 | 不参与签名 |
| datas.amount | number | 是 | 面值，用于匹配产品 |
| datas.operator_id | string | 是 | 运营商名称，须包含「移动」「联通」或「电信」 |
| datas.prov_code | string | 否 | 省份 |

```json
{
  "app_key": "kk_key",
  "sign": "小写MD5",
  "timestamp": "1730000000",
  "user_order_id": "KK10001",
  "target": "13800138000",
  "goods_id": "100",
  "goods_name": "全国移动100元",
  "datas": {
    "amount": 100,
    "operator_id": "移动",
    "prov_code": "广东"
  }
}
```

响应：

| 字段 | 说明 |
|---|---|
| code | SUCCESS 接收成功或订单已存在；FAIL 拒绝 |
| message | 原因。常见：验签失败、充值号码无效、号码命中黑名单、运营商识别失败、暂无配置帮充产品、未找到有效KK配置或推单已关闭 |

```json
{ "code": "SUCCESS", "message": "接收成功" }
```

### 客客帮查单

`POST /open/v1/kk/query`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| user_order_id | string | 是 | 客客帮订单号 |
| app_key | string | 否 | 传入且带 sign 时验签 |
| sign | string | 否 | 签名规则与推单相同 |

```json
{
  "app_key": "kk_key",
  "sign": "小写MD5",
  "user_order_id": "KK10001"
}
```

成功：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "status": 1,
    "rsp_info": "充值中",
    "rsp_time": 1730000000
  }
}
```

失败时 code 为 1，data 为 []。message 为「缺少 user_order_id」「验签失败」或「订单不存在」。

### 蜜蜂签名

除 sign、datas 外，参数名升序。空值不参与。按 key 与 value 直接拼接，不加 = 和 &，末尾接 AppSecret，MD5 小写。

```
app_keymf_keytarget13800138000timestamp1730000000user_order_idMF10001vender_id10086{AppSecret}
```

| goods_name | string | 否 | 商品名称 |
| datas | object | 是 | 不参与签名。amount、operator_id、prov_code 含义与客客帮相同 |

```json
{
```

## 我们的对接方式（驱动 `jidesheng`）

- 接口参数：接口域名（`https://上游域名`，不含 `/open/v1`；下单 `/open/v1/checkout`、查单 `/open/v1/orders`、余额 `/open/v1/accounts`、商品列表 `/open/v1/catalog` 写在驱动里）、代理编号 `userNo`、商户密钥 `secretKey`。服务器出口 IP 要加到上游代理后台的白名单里，否则全部返回 1006。
- 回调地址自动生成（`回调域名/notify/supplier/{供应商编码}`），每单随下单作为 `notifyUrl` 传过去。
- 只接话费，不接撤单、自来单（客客帮、蜜蜂）。字段对应：`clientOrderNo` = 提交单号 `attempt_no`，`phone` = 手机号，`productId` = 供应商商品编码（可从商品列表里选）。上游返回的 `orderNo` 存为供应商订单号；查单按 `clientOrderNo` 查。
- 全部接口 POST JSON，带 `userNo` 和 13 位毫秒 `timestamp`。签名：去掉 `sign`、null 和空串（数字 0 参与），按参数名 ASCII 升序拼 `k=v&...`，末尾拼 `&secretKey=`，md5 转大写；数组用英文逗号拼成一个值。空值参数不发。
- **回调带签名**，用同一算法验签（去掉 `sign` 和空字段），不对回 `fail`（HTTP 400）；通过后按回调里的 `orderStatus` 处理，回 `success`，不用再查单。
- 余额取 `data.balance`。商品列表取 `data`（不带筛选条件，2 秒内只能查一次）：`productId` 作编码、`name` 作名称、`price` 作进价、`faceValue` 作面值，`carrier` 1 / 2 / 3 对应移动 / 联通 / 电信，`category`、`type` 作为补充说明；返回 2003（无匹配产品）时列表为空。

| 情况 | 结果 |
|---|---|
| 下单 `code=0` | 受理，处理中，等回调 / 查单 |
| 下单 `code=3001` 重复提交 | 处理中（这个 `clientOrderNo` 上游已经有单，不能判失败） |
| 下单 `code=9000` 服务错误 | 不知道建没建单，立即转异常订单并标为人工处理单（见 docs/project.md 2.5） |
| 下单其他 `code`（1001～1006 鉴权 / IP / 账户、2001 / 2002 参数和号码、3002 下架、3003 下单失败或余额不足、9001 系统维护等） | 失败，换下一个供应商 |
| 下单网络超时、连不上、返回无法解析或没有 `code`（没有拿到返回值） | 立即转异常订单并标为人工处理单 |
| 查单 / 回调 `orderStatus=SUCCESS` | 成功 |
| 查单 / 回调 `orderStatus=FAILED`（充值失败、撤单退款、返销） | 失败；订单已成功后又来 `FAILED`（返销）不自动改，记 error 日志，人工核对后在后台冲正 |
| 查单 / 回调 `CREATED` / `PROCESSING` / `PENDING_SUPPLEMENT` 或其他 | 处理中 |
| 查单 `code=2003` 查不到 | 只记录，订单状态不动；标记「查无此单」，异常订单人工点查单时置为失败并通知商户（见 docs/project.md 2.5） |
| 查单其他报错、返回的 `clientOrderNo` 对不上、没拿到返回 | 处理中，只记录 |
