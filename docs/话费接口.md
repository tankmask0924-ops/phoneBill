# 话费接口（皮口袋）

## 签名算法

接口中所有标明需要参与签名的参数按照ASCII码从小到大排序，拼接成形如：param1aparam2bparam3param4d，注意，空值也要参与（如param3）

影音会员示例(/api/video-member/submit)：equity_number1638861816021merchant_no11705099001294098432merchant_order_no91675220213notify_urlhttp://106.54.222.93:8002/TestApi/notifyproduct_no31555504031370186752

在末尾拼接渠道分配的密钥：xxxxxxxxxxxxxxxxxxxxxxxxxxxx。如上拼接：param1aparam2bparam3param4d xxxxxxxxxxxxxxxxxxxxxxxxxxxx

影音会员示例(/api/video-member/submit)：
equity_number1638861816021merchant_no11705099001294098432merchant_order_no91675220213notify_urlhttp://106.54.222.93:8002/TestApi/notifyproduct_no31555504031370186752ad4bde88dfe44ba393264528de2e073f

对拼接后的字符串进行MD5并转成小写，即得到签名sign

## 话费接口（产品编码下单）

URL：/api/order/phone-by-product

### 请求参数（JSON）

| 参数名 | 是否必填 | 参与签名 | 说明 |
| --- | --- | --- | --- |
| merchant_no | 是 | 是 | 平台商户编号 |
| merchant_order_no | 是 | 是 | 商户系统订单号<br>要保证唯一 |
| product_no | 是 | 是 | 产品编码 |
| num | 是 | 是 | 数量 |
| equity_number | 是 | 是 | 充值号码 |
| notify_url | 是 | 是 | 回调地址 |
| sign | 是 | 否 | 签名结果，规则见2. |
| device_type | 否 | 否 | 手机、固话、宽带<br>不是必填的 |

### 请求样例

```json
{
    "merchant_no": "81447134257641295872",
    "merchant_order_no": "3391675220213",
    "product_no": "31637273772136468485",
    "num": 1,
    "equity_number": "18800000000",
    "notify_url": "http://10.0.1.0:8002/TestApi/notify",
    "sign": "7626ed77f4ca3ca4e66f4ceda2ae68d7"
}
```

### 返回参数（JSON）

| 参数名 | 是否必填 | 是否签名 | 说明 |
| --- | --- | --- | --- |
| code | 是 | 是 | 结果代码 |
| message | 是 | 是 | 结果说明 |
| data | 否 | 是 | 成功时有值 |
| &emsp;&emsp;orderNo |  |  | 订单号 |
| &emsp;&emsp;merchantOrderNo |  |  | 商户订单号 |
| &emsp;&emsp;price |  |  | 价格 |
| sign | 是 | 否 | 签名规则见2 |

### 返回样例

```json
{
  "code": 1000,
  "message": "成功",
  "sign": "97dd25fe57324dfcb296e48a62bb5946",
  "data": {
    "orderNo": "101447915098520817664",
    "merchantOrderNo": "3391675220213",
    "price": 48.5
  }
}
```

## 订单结果回调通知

通知回调为Http Post 请求，ContentType为application/json，请求报文为Json，回调接收成功后请返回success。如果系统收不到该字符串，会重试10次

### 请求参数（JSON）

| 参数名 | 是否必填 | 参与签名 | 说明 |
| --- | --- | --- | --- |
| MerchantOrderNo | 是 | 是 | 商户系统订单号 |
| MerchantNo | 是 | 是 | 平台商户编号 |
| Payment | 是 | 是 | 实付款 |
| Status | 是 | 是 | 状态<br>Success 成功<br>Failure 失败 |
| ChannelExtraInfo | 否 | 是 | 凭证信息<br>直充订单返回凭证单号<br>卡券订单返回卡券数据，为JSON格式的字符串<br>Json字段包括以下字段<br>cardno 卡号<br>cardpwd 密码<br>以上两个字段为肯定存在的<br>以下的字段为不一定存在的<br>qrcode 二维码<br>msg 消息<br>deadline 有效期<br>自助下单订单返回下单结果数据，为JSON格式的字符串<br>以上示例在表格后边 |
| Sign | 是 | 否 | 签名结果，规则见2.<br>签名参数区分大小写 |

## 错误码

| 代码 | 接口类型 | 说明 |
| --- | --- | --- |
| 1000 | 下单、查询 | 成功（代表请求成功，不是处理成功） |
| 1001 | 下单、查询 | 验签失败 |
| 1002 | 下单、查询 | IP不正确 |
| 1003 | 下单 | 订单号重复，代表订单已经提交 |
| 1004 | 下单 | 额度不足，余额或信用额度不足 |
| 1005 | 下单 | 价格配置不正确 |
| 1006 | 下单 | 匹配参数值不能为空 |
| 1007 | 下单 | 系统繁忙 |
| 1008 | 下单、查询 | 商户号不存在（该状态下返回的签名使用的key为空） |
| 1011 | 下单 | 禁止进单 |
| 1012 | 下单 | 产品Key不正确 |
| 2001 | 查询 | 查不到订单 |

## 我们的对接方式（驱动 `pikoudai`）

- 接口参数：接口域名（`https://上游域名`，下单 `/api/order/phone-by-product`、查单 `/api/order/getorder`、余额 `/api/merchant/balance` 写在驱动里）、商户编号（`merchant_no`）、密钥；回调地址按系统配置的回调域名自动生成（`回调域名/notify/supplier/{供应商编码}`），每单随下单请求传过去。
- 只接话费产品编码下单，不传 `device_type`。字段对应：`merchant_order_no` = 提交单号 `attempt_no`，`product_no` = 供应商商品编码，`equity_number` = 手机号，`num` 固定 `1`。上游返回的 `orderNo` 存为供应商订单号。
- 全部接口 POST JSON。签名按「签名算法」：去掉 `sign`，按参数名 ASCII 升序，键和值直接相连（空值也参与），末尾拼密钥，md5 小写；已用文档里的影音会员示例核对。
- 回调按收到的全部字段（去掉 `Sign`，字段名区分大小写）验签，并核对 `MerchantNo`，通过后回 `success`。`Payment` 如果是 JSON 数字，按报文里的原样（比如 `98.80`）参与验签。
- 响应里也有 `sign`，但 `data` 是嵌套对象，文档没说怎么拼，暂不验。
- 上游没有商品列表接口，供应商商品编码要管理员手动填。

| 情况 | 结果 |
|---|---|
| 下单 `code=1000` | 处理中，等回调 / 查单 |
| 下单 `code` 不是 1000（含 1003 订单号重复、1007 系统繁忙、1001～1012 校验类和表外的码） | 失败，换下一个供应商（2026-10-15 定：上游有返回、不是成功码就判失败） |
| 下单网络超时、连不上、HTTP 出错、返回无法解析（没有拿到返回值） | 立即转异常订单并标为人工处理单：查单结果只记录，回调明确成功 / 失败时交回正常流程（见 docs/project.md 2.5） |
| 查单 / 回调 `Success` | 成功 |
| 查单 / 回调 `Failure` | 失败 |
| 查单 / 回调 `Processing` 或其他 | 处理中 |
| 查单 `code=2001` 查不到订单 | 只记录到这次提交上，订单状态不动（下单受理了就以下单为准，2026-10-15 定）；一直没结果的到时转异常人工处理 |
| 查单 `code` 其他非 1000、`merchantOrderNo` 对不上、没有 `orderStatus` | 处理中，到时转异常人工处理 |
| 回调验签不通过、`MerchantNo` 对不上 | 不采用，回 `fail` |
