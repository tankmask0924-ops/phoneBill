## 1. API(接口)调用说明

### 1.1. 查询账户余额接口

#### 1.1.1. 调用方式post/get表单

Content-Type : application/x-www-form-urlencoded，不是json

请求参数:

| 参数名称 | 类型 | 必填 | 备注 |
| --- | --- | --- | --- |
| szAgentId | Integer(10) | 是 | 客户ID(纯数字ID如200000） |
| szVerifyString | String(42) | 是 | 签名 |
| szFormat | String(8) | 否 | 返回格式:json(默认)或xml |

#### 1.1.2. 加密参数（固定）

32位标准Md5加密后小写(这里的xxx为具体的参数值szKey为密钥)

```
szVerifyString=Md5(szAgentId=xxxx&szKey=xxxx)
```

#### 1.1.3. 请求返回内容

| 参数名称 | 类型 | 备注 |
| --- | --- | --- |
| nRtn | Interger | 详见4.2接口状态映射码 |
| szAgentId | String | 客户ID |
| fBalance | Decimal | 帐号余额 |
| fCredit | Decimal | 帐号信用额度 |
| szRtnCode | String | 返回码(以返回状态值为准) |

#### 1.1.4. 返回内容示例

XML格式：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<return>
<nRtn>0</nRtn>
<szAgentId>200000</szAgentId>
<fBalance>0.00</fBalance>
<fCredit>0.0</fCredit>
<szRtnCode>查询成功</szRtnCode>
</return>
```

2、JSON格式：

```json
{
  "nRtn": 0,
  "szAgentId": "200000",
  "fBalance": 0.0,
  "fCredit": 0.0,
  "szRtnCode": "查询成功"
}
```

#### 1.2.5. 充值请求注意事项

- 服务器时间请调整为准确的北京时间，时间戳晚于我方服务器时间1分钟则判定该次请求为过期请求。
- 充值请求收到的结果为收单结果，收单成功不代表充值成功。
- 充值请求的商户订单号由商户自行生成，订单号生成规则为字母或数字组合，商户订单号字符串长度建议为16-32位。如果商户订单号不符合生成规则（如：包含其他非法字符、订单号长度超长）造成的订单异常损失由商户自行承担。
- 商户订单号为请求的唯一标识。

### 2.3. 代充卡号卡密加密

AES加密密钥为szVerifyString签名密钥的前16位

AES加密向量为szVerifyString签名密钥的后16位

AES算法模式补码：AES/CBC/PKCS5Padding

```java
      /**
       * 加密
       *
       * @param sSrc
       *            加密原串
       * @param sKey
       *            加密密钥
       * @return
       * @throws Exception
       */
      public static String encrypt(String sSrc, String sKey, String sIv) throws Exception {
          // Key为空null
          if (sKey == null) {
              return null;
          }
          // 判断Key是否为16位
          if (sKey.length() != KEYSIZE) {
              return null;
          }
          byte[] raw = sKey.getBytes(charsetName);
          SecretKeySpec skeySpec = new SecretKeySpec(raw, aes);
          Cipher cipher = Cipher.getInstance("AES/CBC/PKCS5Padding");// "算法/模式/补码方式"
          IvParameterSpec iv = new IvParameterSpec(sIv.getBytes(charsetName));
          cipher.init(Cipher.ENCRYPT_MODE, skeySpec, iv);
          byte[] encrypted = cipher.doFinal(sSrc.getBytes(charsetName));
          return  java.util.Base64.getEncoder().encodeToString(encrypted);
      }
```

## 我们的对接方式（驱动 `xuanjie`）

- 接口参数：接口地址（`http://IP:端口`，下单 `/plat/api/old/submitorder`、查单 `/plat/api/old/queryorder`、余额 `/plat/api/old/queryBalance` 写在驱动里）、客户ID（`szAgentId`）、密钥（`szKey`）；回调地址自动生成（`回调域名/notify/supplier/{供应商编码}`），每单随下单传 `szNotifyUrl`。
- 只接话费。字段对应：`szOrderId` = 提交单号 `attempt_no`，`szPhoneNum` = 手机号，`nMoney` = 整数面值，`nSortType` 1 移动、2 联通、3 电信（其他运营商不提交，直接失败换下一家），`nProductClass` / `nProductType` 固定 `1`，常规话费不传 `szProductId`。上游没有自己的订单号，供应商订单号留空。
- 全部接口表单 POST，每次带 `szFormat=json`（不参与签名）。签名按 1.1.2 / 1.2.2 / 1.4.2 的固定顺序拼 `k=v&...`，末尾拼 `&szKey=密钥`，md5 小写；`szTimeStamp` 用北京时间 `yyyy-MM-dd HH:mm:ss`。
- 回调按 1.3.2 的顺序（`szAgentId`、`szOrderId`、`szPhoneNum`、`nDemo`、`fSalePrice`、`nFlag`，值按收到的原样，`szRtnMsg` 不参与）验签并核对 `szAgentId`，通过回 `ok`，不通过回 `fail`。
- 余额取 `fBalance`（不含信用额度 `fCredit`）。30 秒只能查一次，返回 `5002` 时提示「查询太频繁，30 秒后再刷新」；后端已把余额结果缓存 30 秒，正常刷新列表不会触发。

| 情况 | 结果 |
|---|---|
| 下单 `nRtn=0` | 处理中，等回调 / 查单 |
| 下单 `nRtn` 不是 0：`1000`、`1001`、`1003`、`1004`、`1006`、`2001`、`2002`、`2003`、`2020`、`2021`、`2030`，`3003` 订单号重复（文档写的是等待结果，2026-10-16 定判失败），以及文档写「未确认（人工核实）」的表外的码（2026-10-25 定判失败） | 失败，换下一个供应商（上游有返回码、不是 0 就判失败） |
| 下单网络超时、连不上、HTTP 出错、返回无法解析（没有拿到返回值） | 立即转异常订单并标为人工处理单：上游结果只记录，状态和回调全部人工（见 docs/project.md 2.5） |
| 查单 `5012` | 成功 |
| 查单 `5013` | 失败 |
| 查单 `5011` | 处理中 |
| 查单 `5005` 订单不存在 | 只记录到这次提交上，订单状态不动（下单受理了就以下单为准；提交异常的单已是人工处理单，提交 10 分钟后由人工补充或判失败） |
| 查单 `5002` 查询频繁、`5003`、`5004`、表外的码、返回订单号对不上、没拿到返回 | 处理中，不处理订单，到时转异常人工处理 |
| 回调 `nFlag=2` / `3` | 成功 / 失败 |
| 回调其他 `nFlag` | 回 `ok`，不处理订单 |
