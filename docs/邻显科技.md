- 所有请求和响应数据头类型 application/x-www-form-urlencoded 或者 application/json

## 请求参数：

- POST

## 响应数据格式：

| 参数名 | 必选 | 类型 | 说明 |
| --- | --- | --- | --- |
| message | 是 | string | 响应正确或者错误的提示信息 |
| data | 是 | object | 响应数据内容 |
| code | 是 | int | 响应状态码：0为正常，其他值为错误 |

## 签名生成：

代理商可以从 系统管理—查看设置 中拿到属于自己的 APPID 和 APPSECRET ,遵循一下规则签名。

第一步 参数名ASCII码从小到大排序（字典序），区分大小写，参数为空也参与签名。<br>第二步 将排序好的参数使用URI参数的方式拼接密钥，得到字符串 waitSignParamsStr。<br>第三步 把 APPSECRET 使用 ‘&secret=APPSECRET’ 方式拼接到waitSignParamsStr字符结尾，得到字符串waitSign。<br>第四步 对waitSign字符串MD5摘要，并转换为全大写。

注意：国漫订单加签时，需要把国家地区部分用urlencode转义<br>例如mobile参数的值为13800000000_中国台湾,中国香港,中国澳门

签名前参数串为（含国漫地区示例）：<br>appid=WBHFKYRPK0&mobile=13800000000_%E4%B8%AD%E5%9B%BD%E5%8F%B0%E6%B9%BE%2C%E4%B8%AD%E5%9B%BD%E9%A6%99%E6%B8%AF%2C%E4%B8%AD%E5%9B%BD%E6%BE%B3%E9%97%A8&product_id=1000&secret=LcI7xSAoE84fPpo6xJ2Y3TqK7yD7Bxh0<br>签名结果为：D7875CDB565DAB2F99A30CEBB1FDCABA

## PHP示例

```
$params = [
    'appid'=>'WBHFKYRPK0'
];
//第一步、参数名ASCII码从小到大排序（字典序），区分大小写，参数为空也参与签名。
ksort($params);
//第二步、将排序好的参数使用URI参数的方式拼接密钥，得到字符串 waitSignParamsStr。
$waitSignParamsStr = http_build_query($params);// 此时$waitSignParamsStr = 'appid=WBHFKYRPK0'

//第三步、使用 '&appsecret=APPSECRET' 方式拼接到waitSignParamsStr字符结尾，得到字符串waitSign。
$waitSign = $waitSignParamsStr.'&secret=LcI7xSAoE84fPpo6xJ2Y3TqK7yD7Bxh0';// 此时$waitSign = 'appid=WBHFKYRPK0&secret=LcI7xSAoE84fPpo6xJ2Y3TqK7yD7Bxh0'

//第四步、对waitSign字符串MD5摘要，并转换为全大写。
$sign = strtoupper(md5($waitSign));//此时$sign = '9BFF8AB5DE616B012958ADBB9A802A05';
```

# 回调通知

## 回调地址：

代理商可以从 系统管理—查看设置 中编辑更改回调地址，回调地址必须是公共网络可以访问的地址，系统将会使用POST方式发起回调。

## 回调参数：

回调提供的sign参数可以使用签名方式进行验签，为了避免伪造请求带来不必要的麻烦，请验签之后再执行必要的业务。

## 响应数据格式：

| 参数名 | 必选 | 类型 | 说明 |
| --- | --- | --- | --- |
| error_msg | 是 | string | 充值失败说明 |
| order_no | 是 | string | 系统订单号 |
| isp_order_no | 否 | string | 运营商透传流水号 |
| out_order_no | 否 | string | 商户订单号 |
| order_status | 是 | string | 状态枚举,PASS=已提交；RUNNING=充值中；FAILED=充值失败；FINISH=充值成功 |
| order_status_text | 是 | string | 状态中文说明 |
| sign | 是 | string | 签名，示例如下 |

## 接口响应说明：

接入方必须响应回调的请求，回调处理成功响应success字符串，且HTTP状态码为200。<br>为了保证回调通知的成功率，仅当接入方未正确响应回调请求，平台将会多次延迟发起回调通知。<br>每次通知时间间隔为第一次为2s，第二次为5s，第三次为15s，25s，40s，60s，120s，240s，1800s，3600s，仅最多通知11次，过后将不再通知接入方订单结果。<br>回调响应超时时间为 5s。

## 我们的对接方式（驱动 `linxian`）

- 接口参数：接口域名（`http://上游域名`，下单 `/api/recharge`、查单 `/api/order`、余额 `/api/balance`、商品列表 `/api/product` 写在驱动里）、`APPID`、`APPSECRET`。
- **回调地址不随单传**：要在上游后台「系统管理—查看设置」里填自动生成的回调地址（`回调域名/notify/supplier/{供应商编码}`）。
- 只接话费。字段对应：`out_order_no` = 提交单号 `attempt_no`，`mobile` = 手机号，`product_id` = 供应商商品编码（上游产品 id，可从商品列表里选）。上游返回的 `order_no` 存为供应商订单号。
- 全部接口表单 POST。签名按「签名生成」：去掉 `sign`，按参数名 ASCII 升序用 `http_build_query` 拼成 URI 参数（值做 URL 编码，空值也参与），末尾拼 `&secret=APPSECRET`，md5 转大写；已用文档里的两个示例核对。
- 回调按收到的全部字段（除 `sign`）同样验签，表单和 JSON 都能收；通过回 `success`，不通过回 `fail`。
- 余额取 `data.balance`。商品列表取 `data.list`：`operator` 中文多个用逗号隔开（移动 / 联通 / 电信 / 广电）；只有 `unit` 是「元」时 `capacity` 才当面值；`region` 作为补充说明；接口没有上下架字段，全部按在售。
- 查单用 `/api/order`（只传 `out_order_no`），`/api/v2/order` 卡单查询暂不用；`40001` 无订单也按 v2 的含义识别。

| 情况 | 结果 |
|---|---|
| 下单 `code=0` | 处理中，等回调 / 查单 |
| 下单 `code` 不是 0 | 失败，换下一个供应商（上游有返回码、不是成功码就判失败） |
| 下单网络超时、连不上、HTTP 出错、返回无法解析或没有 `code`（没有拿到返回值） | 立即转异常订单并标为人工处理单：上游结果只记录，状态和回调全部人工（见 docs/project.md 2.5） |
| 查单 `order_status=FINISH` | 成功 |
| 查单 `order_status=FAILED` | 失败 |
| 查单 `order_status=PASS` / `RUNNING` 或其他 | 处理中 |
| 查单 `code=40001` 无订单 | 只记录到这次提交上，订单状态不动；一直没结果的到时转异常人工处理 |
| 查单其他非 0 的 `code`、没有 `order_status`、返回订单号对不上、没拿到返回 | 处理中，不处理订单 |
| 回调 `order_status=FINISH` / `FAILED` | 成功 / 失败（`error_msg` 作为失败原因） |
| 回调 `PASS` / `RUNNING` 或其他 | 回 `success`，不处理订单 |
